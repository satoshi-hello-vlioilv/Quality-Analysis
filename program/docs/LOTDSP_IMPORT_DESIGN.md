# ロット問い合わせ（LotDsp）「進度情報」からの工程データ取込

状態: **実装済み**（2026-09-27）。社内のログイン不要な範囲は**このアプリだけで読める**（2026-09-29・§1.2）。
ログインが要るとき（VPN）は **LotDsp の窓**（2026-10-02・§1.4。ログインは利用者・続きはアプリ）。
**版 3.0.0（2026-10-04）で、Edge 拡張 LotData-Link の道を外した**（拡張はブラウザ版の画面にだけ入り、ブラウザ版を外したため。§1.5）。
下の §1〜§1.1・§4 の拡張の仕組みは、外す前の記録として残す。
2026-09-28 に、WaveLog 同梱の拡張（`program/lotdsp-ext`・版 1.1.1 まで）から単独のアプリへ切り出された（WaveLog §9.521）。

## 1. 仕組み（版 2.x まで。拡張の道は版 3.0.0 で外した）

LotDsp は AngularJS の画面で、表はブラウザの中で描かれます。VPN ではログインが要り、ログイン済みの状態は Edge の中にしかありません。
そのため Python から HTTP で取りに行く方式では読めません（以前あった `data_source.mode = "remote"` は 2026-09-30 に削除）。**表を読むのは Edge 拡張 LotData-Link**
（ログインを代行している拡張と同じもの）で、列の意味づけはこのアプリの Python 側 1 箇所で行います。

```
[転写計算アプリ]                    [LotData-Link（Edge 拡張）]              [LotDsp（別タブ）]
「検索」（検索ボタンは1つ）
  └ CustomEvent tpa:lotdsp-fetch ─▶ app-transfer.js ─▶ background.js
                                     空のタブに頼み(job)を置いてから LotDsp を開く ─────▶ 表示
                                                                   lotdsp-login.js: VPN ならログイン
                                                                   lotdsp-relay.js: 頼みのあるタブでだけ動く
                                                                     ロット番号を入れて「検索」
                                                                     →「進度情報」タブ
                                                                     → 実績の行数が落ち着いたら画面の HTML
                                     background.js ◀──────────────────────┘
  app-transfer.js ◀─ 結果（LotDsp のタブは閉じてアプリへ戻る）
  └ CustomEvent tpa:lotdsp-result
POST /api/lots/import-lotdsp（同じオリジン）
  └ app/services/lotdsp_progress.py … 見出しの文字で列を探す → Lot
既存の /api/calculate で再計算
```

- **人や WaveLog が開いた LotDsp とは分けてあります。** 取込用のスクリプトは、転写計算アプリが開かせたタブでだけ動きます。
  ログインを押すのは LotData-Link の `lotdsp-login.js` だけです（二重押しなし）。
- **合図の名前（`tpa:lotdsp-fetch` ほか・`data-tpa-lotdsp-ext`）は LotData-Link との約束**です（LotData-Link の `docs/DESIGN.md` §4）。
  拡張が版 1.x（以前の WaveLog 同梱）を名乗ったら、ヘッダーの「データ元」の札に ⚠ を付けて入れ替えを案内します（VPN の画面で止まる版のため）。
- **鋳造番号は使いません。** linkkey（ロット番号＋鋳造番号）は使わず、ロット番号の欄に入れて「検索」を押します。
- **新しい HTTP の口は外へ向けて開けていません。** 拡張→アプリはタブ間のメッセージで画面へ渡し、画面が同じオリジンの API を呼びます。
- 拡張が無い PC 向けの予備: 進度情報の画面を **Ctrl+A → Ctrl+C → 取込ダイアログに Ctrl+V**、または「名前を付けて保存」した HTML を選ぶ。
  どちらも同じ `lotdsp_progress.py` で読みます。

### 1.1 画面の「検索」（2026-09-28 統合）

- 検索ボタンは1つ。拡張があれば上の流れ、無ければ貼り付けダイアログを開く。サンプルデータの検索（`/api/lots/<No>`）は画面から外した
  （API は残していたが、使う所が無いため 2026-09-30 に削除。見本の1ロット〈L237F51〉と remote 方式・設定の `data_source` も）。起動時の自動検索もやめた（検索のたびに LotDsp のタブが開くため）。前回取り込んだロット番号を入れた状態で起動する。
- 押した時点でロット番号をクリップボードへ写す。拡張の段階が 25 秒進まなければ、「LotDsp のタブで貼り付けて『検索』を押せば続きは自動」
  と案内する（手で検索しても、結果が出た時点で拡張が進度情報を読んで返すため）。
- 画面の評価は 15 項目（ボタンが1つ・起動時に検索しない・大文字で拡張へ渡す・取込で表が埋まる・止まったときの案内・遅れた結果の取込・
  拡張なしのダイアログ ほか）を、拡張を模したスクリプトを入れた Chromium で確かめた。

### 1.3 LotDsp の API をログインなしで読む（2026-10-01・LotSearch と同じ道）

LotSearch（別リポジトリ・`lot_api.py`）は、LotDsp の画面が裏で呼ぶ `POST {LotDsp}/service/lotdsp/search//searchAction`
（JSON `{lotNo, kensaNo, nowPage}`）を、**Cookie・認証を付けずに**呼んで基本情報（`entity.staffCommonBean`）を読んでいる。
社内でも VPN でもログインなしで読めるという報告を受けて、同じ道を取り入れた（`app/services/lotdsp_api.py`）。

- **確かめられていないこと**: ログインなしで読めること自体は、開発環境（社外）から LotDsp へ届かないため確かめられていない。
  そこで実際に使う PC で確かめられるようにした（下の「学ぶ」で、ログインなしで応答が返った記録を `lotdsp_api_map.json` の `login_free` に残し、
  `/api/lots/lotdsp-api/status` と `/api/config` の `lotdsp_api` で見られる）。進度情報（設備の実績・設計）の項目名は LotSearch のコードにも無い。
- **学ぶ**: 項目名を決め打ちしない。画面（見えない Edge・LotData-Link・貼り付け）で読めたら、同じロットを API でも引き（裏で）、
  画面の値と同じ値を持つ項目を列ごとに探して候補を絞る（`learn`）。数は丸めの違い、日付は書き方の違いを許して比べる。
  - 決める条件: 候補が1つに絞れ、値の手がかりが2回以上そろったとき（`MIN_SEEN`）。LotSearch が実際に読めている基本情報の項目だけは最初から信頼。
  - 値が空・0 の列（前オフ・後オフなど）は手がかりにならないので決めない。画面の class 名が列とずれている（前ｵﾌ・長さ・肉厚）ため、名前の目安では決めない。
    取込に要る列がすべて決まるまでは使わない（ready でない）。要らない列（分割の枚本）だけは名前を目安に採る。
  - 食い違う値が出たら、その列を決め直す（使えないに戻る）。並びの場所が替わったら学び直す。
  - 学んだ対応は作業場所の `lotdsp_api_map.json`。キーの名前と学んだ記録だけで、ロットの値は置かない。
- **応答の書き方の違い（1.4.1）**: 日付は ISO・経過ミリ秒（13桁）・秒（10桁）・タイムゾーンつき（Z・+0900。この PC の時刻にして比べる）を照らせる。
  基本情報は `staffCommonBean` 以外にあってもよい（応答全体の値から探し、道すじ `staffMaterialBean.komoku.hijuu2` のように覚える。以前の版の項目名だけの記録は読み込むときに道すじへ直す）。
- **同じ内容が複数の場所にあるとき（1.4.2）**: 基本情報は、応答の中に同じ内容が2か所（元データの `icasBean` と表示用の `staffCommonBean` など）にあることがある。
  どのロットでも同じ値（比重 2.73 など）だと、どちらも画面と一致し続けて1つに絞れない。基本情報の列だけ、`TIE_SEEN`（3）ロット以上で一致し続けた複数の候補は、
  どれを読んでも同じ値だったとして先頭の候補（並びは道すじの順）に決める。行の表の列（実績・設計）では決めない（先頭の行の値と同じ別名が複数の行で一致し続けるため、別のロットで食い違うまで待つ）。
  食い違って候補が尽きたら手がかりの回数を 0 に戻し、決め直したあとの1回の一致では決めない。
- **決まらない理由を見る**: 状態の `probe` に、決まらない列ごとの「画面の値の形」と「その行の応答の候補の形」を出す（`shape`: 数字→9・英字→a・かな漢字→あ・型の名前つき。
  例 `float:9.99`・`int:9999999999999`・`str:9999-99-99a99:99:99`）。値は出さない。経過ミリ秒か ISO か、小数の桁か、別の場所か、を見分けるため。
- **読む**: ready のとき、画面の「検索」は最初にこれ（`POST /api/lots/fetch-lotdsp-api`）。工程の組み立ては画面から読んだときと同じ
  （`lotdsp_progress.build_lot`: 設備マスタで絞る・巻出しは初期値）。ロット番号が頼んだものと違えば止める。
  該当なしはそのまま言い、それ以外で読めなければ次の道（見えない Edge → LotData-Link → 貼り付け）へ回す。
- **待ち状態の窓（1.4.3）**: 速くても数秒かかるので、読んでいるあいだは、ほかの道と同じ進行の窓（`fetchModal`）を出す。段階は「LotDsp の API に問い合わせ → 取り込み・計算」の2つ、経過秒、「中止」（Esc）。
  中止は fetch を打ち切り（`AbortController`）、取り込まず、ほかの道へも回さない。読めなかったとき（該当なし以外）は、窓を閉じて次の道の窓へ移る。
- **応答の全項目の調査（1.5.0）**: `GET /api/lots/lotdsp-api/survey?lot=ロット番号`（`lotdsp_api.survey`）。応答（`entity` の外も含む全体）をたどり、項目ごとに
  道すじ・型・形・空でない件数（`of` 件中 `nonnull`）・このアプリが使う用途（`used_for`）を返す。実績・設計のように並びの中の項目は `道すじ[]` として要素を合わせて数える。
  `unused_non_empty` は、値が入っているのにまだ使っていない項目。何も覚えず・書き換えない。既定は形だけ。`&values=1` で値も入れる（この PC の画面で見るだけ。外部へ渡さない）。
  - **画面のほかのタブ（製造情報・試験情報・品質情報・クラッド情報・焼鈍情報・引当情報）**は、タブを押したときに別の問い合わせをしている可能性があり、検索の応答には入っていないかもしれない。
    通信先を推測で探すことはしない。本物の通信先は Edge の開発者ツール（F12 → ネットワーク → Fetch/XHR）で、LotDsp の画面のタブを押して出る要求の URL と、要求の項目名（値は伏せる）を見て分かる。
- **項目 ↔ 画面の見出し の紐づけ（1.6.0）**: `/lotdsp-link`（`lotdsp_link.py`・`POST /api/lots/lotdsp-api/link`）。保存した LotDsp の画面（タブごとの HTML）と、同じロットの API の応答を、**値の一致**で照らす。
  - 画面の HTML には、値がどの項目かを示す印（束縛の式）が残らない。進度の表の部品名は項目名に似るが、列とずれる所がある（長さの列が `jbfo` など）ので使わない。
  - 欄ごとに見出しの候補を作る（表の見出し行＞上＞左＞行頭。この順に確からしい）。記号だけの字・数・日付・長い字は見出しにしない。応答の値に当たった欄の字は値なので見出しにしない。
  - 値が目立たないもの（1・0・1文字）は照らさない。数は画面の桁で丸めた一致（整数の欄は応答も整数のときだけ。先頭が 0 の番号は字として）、日付は ISO・経過ミリ秒・タイムゾーンつきを許す。
  - 設備ごとの並び（`道すじ[].項目`）は、画面の表の列と行の順で照らし、照らせた行の 8 割以上が一致したら、その列の見出し（`kind: 列`）。
  - 同じタブを別のロットで2つ以上渡すと、どのロットでも残った見出しだけが残る。状態: **確定**（残った見出しで票が抜けて多く、2ロット以上または並びの列）／**候補**／**食い違い**（ロットごとに別の見出し）。
  - 出力は道すじと見出しだけで、値を含まない（`screen_only` は、応答に当たらなかった画面の見出し）。何も保存しない。
- **ログインはしない**（Cookie・Authorization・パスワードを送らない。社内のプロキシも通さない）。
- 設定 `lotdsp_import.api.enabled=false` で、この道も学ぶための問い合わせも使わない。`search_url` などは `api.*` で変えられる。
- 試験: `tests/test_lotdsp_api.py`（疑似の LotDsp を立てて、学ぶ・読む・画面で読んだのと同じ工程・別名の除外・偶然の一致で決めない・
  食い違いの決め直し・Cookie を送らない・読めない理由の言い分け）。

### 1.2 このアプリだけで読む（2026-09-29・拡張なし・社内のログイン不要な範囲）

利用者の指示「VPN 環境だと LotData-Link が必要だが、社内のログイン不要な状態でも今だと必須になってしまっている。
転写計算アプリ単独でも社内のログイン不要な範囲なら問題なく使えるように」。

LotDsp の裏の API は分からない（公開されていない・見本の HTML にも手がかりが無い）ため、**画面を人と同じ道で操作して読む**
方式は LotData-Link と同じにし、動かす役をアプリ（Python）に持たせた。

```
「検索」 → POST /api/lots/fetch-lotdsp {lot_no}
  └ lotdsp_direct.py
      1) LotDsp のサイトへ届くか（HTTP・4 秒）。届かなければブラウザを起こさずに unreachable
      2) この PC の Edge（無ければ Chrome）を --headless=new・使い捨ての一時プロファイル・DevTools のポート 0 で起動
      3) DevTools Protocol（WebSocket・標準ライブラリだけの最小限）で config の searchUrl（url + "#/lotdsp"）を開き、
         lotdsp_direct.js を Runtime.evaluate で入れる（手順は LotData-Link の lotdsp-relay.js と同じ:
         ロット番号を入れて「検索」を1回 → 「進度情報」 → 実績の行数が 3 回同じで描き終わり → 画面の HTML）
      4) ブラウザを閉じ、一時プロファイルを消す
  └ lotdsp_progress.py（拡張・貼り付けと同じ読み方）→ {lot, report}
```

- **ログインはしない。** ログインの欄（`#input_userId` や「ログイン」ボタン）が見えたら何も押さずに `kind: login`（409）。
  ID・パスワードを持つのは LotData-Link だけで、このアプリはパスワードを扱わない。
- 画面（app.js `runSearch`）の順: ①このアプリだけ → ログインが要る・読めない（届かない・Edge が無い・DevTools が止められている）
  なら ②LotData-Link（入っていれば）→ ③貼り付けのダイアログ（理由を最初に言う）。該当なし・形の違いはどの道でも同じ答えなので、
  次へ回さずにそのまま言う。ログインが要ったタブでは sessionStorage に覚え、次からは①を飛ばす（毎回の空振りを省く）。
- 同時に1つだけ（サーバーの錠）。全体の待ちは 60 秒（`lotdsp_import.direct.timeout_seconds`）。
- 会社の設定（Edge のポリシー）でヘッドレス起動・DevTools が止められている PC では `kind: browser` になり、②③へ回る。
  そのときの対処は LotData-Link を入れること（利用者に分かる言葉で理由を出す）。
- 試験: `tests/test_lotdsp_direct.py`（11 件。うち 4 件は本物の Chromium で LotData-Link の見本 LotDsp
  `tests/fixtures/lotdsp_site_fake.html` を読む: 取込・該当なし・VPN の一体型ログインで引き返す・一時プロファイルを消す）。
  画面の評価 16 項目（拡張なしで取り込める・該当なし・拡張なしの VPN は理由つきで貼り付け・拡張ありの VPN は LotData-Link へ回して
  次から拡張を先に・拡張があっても社内では直接・設定で切ればこれまでどおり）。

### 1.4 LotDsp の窓（2026-10-02・版 2.3.0・ログインが要るとき・LotData-Link が無いとき）

利用者の指示「デスクトップ版への一本化を進めて」。LotData-Link（Edge 拡張）はブラウザ版の画面（127.0.0.1:57821）にだけ入り、
デスクトップ版の窓（WebView2）には入らない。そのため、デスクトップ版で VPN（ログインが要る）だと貼り付けしか残らなかった。
これを埋めるため、**ログインは利用者が、続きはアプリが**行う窓を足した（ブラウザ版でも LotData-Link が無ければ使う）。

```
「検索」 → ①見えない Edge（1.2）→ kind: login
  → LotData-Link があれば ②LotData-Link（これまでどおり）
  → 無ければ POST /api/lots/fetch-lotdsp {lot_no, login_window: true}
      lotdsp_direct.py: Edge を見える窓（--app・タブもアドレス欄も無い）で、専用のプロファイル（作業場所の lotdsp-window）で開く
        → lotdsp_direct.js を 1 秒ごとに入れ直す。ログインの欄が見えているあいだ（kind: login）は、窓を前に出し、
          空いているロット番号の欄にだけロット番号を入れて、利用者を待つ（段階 login。画面は「窓でログイン（あなた）」と案内）
        → 欄が消えたら、利用者の押した検索が落ち着くのを 1.5 秒待ってから続きを読む（画面がもうそのロットなら検索し直さない）
        → 読めたら窓をしまう（最小化）。窓は 30 分残して使い回す（ログイン済みならそのまま読む）
```

- **アプリは ID・パスワードに触れず、ログインも押さない**（1.2 の約束のまま）。覚えさせたいときは、その窓の Edge が覚える
  （専用のプロファイルは閉じても消さない。いつもの Edge とは別）。
- ログインを待つのは 5 分（`direct.login_wait_seconds`）。待ちきれなければ kind: login で理由を返し、画面は貼り付けへ。
- 画面はログインが要ったことを覚え（`tpa.lotdsp.route.v2` = "win"）、次からは最初から窓の道で読む。
- 使わないときは `direct.login_window: false`（これまでどおり、LotData-Link か貼り付け）。
- 試験: `tests/test_lotdsp_direct.py` の LoginWindow（5 件・本物の Chromium の見える窓。Linux では xvfb-run）。利用者の手は、
  同じ窓へつないだもう 1 本の DevTools で演じる: 待つ・送ったのは利用者の 1 回だけ（ロット番号はアプリが入れた）・検索し直さない・
  2 回目は使い回してログインを待たない・プロファイルは残す・待ちきれない・中止・頼まれなければ窓を出さない。
  見本（`fixtures/lotdsp_site_fake.html` の ?vpn=1）は、ログイン済みをタブのあいだ覚える（実物はサーバーのセッション。読み込み直しても保たれる）。
  画面の評価 17 項目（ログインが要ると窓の道へ・段階と案内・Esc で中止・次から窓の道・アプリが触れたのはロット番号だけ・取り込む・
  ログイン済みなら飛ばす・待ちきれなければ理由つきで貼り付け・例外なし）。
- **実物の VPN の LotDsp で確かめていない**（下の 6）。

### 1.5 拡張の道を外した（2026-10-04・版 3.0.0）

利用者が VPN で LotDsp の窓を使えると確かめたので（2026-10-04）、デスクトップ版へ一本化し、ブラウザ版とともに LotData-Link の道を外した。

- 画面（app.js）: 拡張の名乗り（`data-tpa-lotdsp-ext`）・合図（`tpa:lotdsp-*`）・拡張の段階表示・古い拡張の警告を外した。

## 2. 取り込む項目

見本（`tests/fixtures/lotdsp_progress_L7150C0.html`・Edge で保存した実物）で確かめた見出しです。
列は**見出しの文字**（NFKC で ｵﾌ／オフ 等をそろえて完全一致）で探し、class 名は使いません（実物の class は列とずれている箇所があります）。

| アプリの項目 | 読む場所 | 備考 |
| --- | --- | --- |
| 設備 `equipment` | 実績「設備」 | |
| 作業日 `work_date` | 実績「日付」 | `26/09/17 17:16:31` |
| 作業後板厚・板幅・重量 | 実績「板厚」「板幅」「重量」 | mm・mm・kg |
| 総オフ前・後 `off_front_m`/`off_back_m` | 実績「前ｵﾌ」「後ｵﾌ」 | 空欄は 0 |
| 分割数(設計) `design_split` | 設計「枚本」（同じ№）。設計と実績で設備が違えば実績「枚本」 | |
| 横割・縦割 | 設計「横」「縦」（同じ№） | |
| 巻出し方向 `unwind` | **初期値「上」**（進度情報に無いため・利用者の指示。`models.DEFAULT_UNWIND`） | 違う工程は表で直す。設備マスタが持つのは「巻取方向」で、面の反転の判定に使う |
| ロット・鋳造・検査・オーダー番号、用途、用途名、比重 | 見出し｜値の小さな表 | 値は正規化しない |
| 製造材質・調質・板厚・板幅・板丈 | 材質の表の「製造」行（オーダー行ではない） | |

- **BOX は最大 25 の可変**。行数を決め打ちせず、№が数の行を全部読みます（3・10・25 行で試験）。
- **設備マスタに無い設備の行は取り込みません**（`lotdsp_import.only_master_equipment`、既定 true）。黙って捨てず、画面の取込結果に
  「取り込まなかった行」として№と設備名を出します。マスタ管理で設備を足して取り込み直せます。
- 設計にだけある行（未実績）は取り込まず「未実績」として出します。
- 実績の「長さ」「肉厚」（巻きの肉厚）は今の計算では使わないため取り込んでいません。「オフ肉厚 前・後」は進度情報に無いので 0 のままです。
- 取込を頼んだロット番号と画面のロット番号が違えば止めます（取り違え防止）。

## 3. 設定（`config/appsettings.json` の `lotdsp_import`）

| キー | 既定 | 意味 |
| --- | --- | --- |
| `url` | `http://nlmfangyweb1a/LotDspWeb/` | 読みに行く LotDsp（このアプリだけで読む最初の画面は `url` + `#/lotdsp`）・予備の取込ダイアログの「LotDsp を開く」 |

| `direct.login_wait_seconds` | `300` | LotDsp の窓で利用者のログインを待つ長さ |
| `direct.browser` | `""` | 裏で動かすブラウザの実行ファイル（空なら Edge → Chrome の既知の場所。「参照先」マスタでも変えられる） |
| `direct.timeout_seconds` | `60` | 1回の検索の待ちの上限 |
| `only_master_equipment` | `true` | 設備マスタに無い設備の行を取り込まない |
| `actual_columns` / `design_columns` / `lot_labels` | `{}` | 見出しの名前が変わったときの上書き（例: `{"off_front_m": "前オフ"}`） |

## 4. 入れ方（版 2.x まで。版 3.0.0 からは要らない）

1. 以前の WaveLog 同梱の拡張（「WaveLog ロット問い合わせ 自動ログイン」）が入っていれば、`edge://extensions` で**先に削除**する
   （2つ入っていると、ログインを二重に押すおそれがあります）。
2. LotData-Link を PC に置き、`edge://extensions` の「開発者モード」→「展開して読み込み」で LotData-Link の `extension` フォルダを選ぶ
   （くわしくは LotData-Link の README。ID・パスワードは1度だけ登録し直しが要ります）。
3. 転写計算アプリを開き直すと、右上の「データ元」の札に LotData-Link の版が出ます（「検索」ボタンにマウスを乗せると読み方が出ます）。
