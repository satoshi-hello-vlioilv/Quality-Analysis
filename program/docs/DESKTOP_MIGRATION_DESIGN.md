# デスクトップ版への移行（Tauri / Rust / Python）

版 2.0.0 から。ブラウザ版（Start.vbs → 127.0.0.1 のポート）はそのまま残し、同じ program フォルダで動くデスクトップ版（`TransferPitchAnalyzer.exe`）を足した。
**版 3.0.0 でブラウザ版を外し、デスクトップ版に一本化した**（§10.4）。§1〜§5 のブラウザ版の話は、なぜ移したかの記録として残す。
この文書は「なぜ・どう分けたか・何で確かめたか・次に何を移すか」を残す。

## 1. 移す前に、ポートが起こしていたこと

ブラウザ版は Python（Flask）が 127.0.0.1:57821 で待ち受け、Edge で開く。このポートが次の不具合と仕組みの元になっていた。

| 起きたこと | それを抑えるために足した仕組み |
|---|---|
| Windows のプロキシ設定が 127.0.0.1 宛てまで社内のプロキシへ送り、動いているアプリが「答えない」ように見えた（2026-09-29） | `local_app.py` のプロキシを通さない問い合わせ |
| 古いサーバーがポートを掴んだまま残り、新しいプログラムと版が混ざった（2026-09-29） | `launch_guard.py` の止め直し・`app_build.fingerprint`・画面の版の照合 |
| ほかのプログラムがポートを使っていると起動できない | `stop.bat`・`process_manager.py`・netstat による持ち主探し |
| ブラウザを閉じたかが分からない | ハートビートと猶予（`lifecycle.py`。裏のタブ・スリープ復帰の例外つき） |
| 起動を待つ画面がポートを推し量る | `loading.html`（`#port=`） |

どれも「ポートを開いて、別のプログラム（ブラウザ）から問い合わせる」ことから来ている。デスクトップ版では、ポートそのものを無くした。

## 2. 役割の分け方（得意な分野ごと）

| 受け持つもの | 何を | 理由 |
|---|---|---|
| **Rust**（`desktop/`・Tauri） | 窓、起動と終了、1つだけ起動、静的ファイル（JS・CSS・three.js）、中身（Python）の監督と起こし直し、外のリンクを Edge で開く | OS の窓・プロセス・ファイルを直接扱える。止まらない・残らないことを型と所有で保証しやすい |
| **Python**（`program/`・そのまま） | 画面の HTML と API のすべて（LotDsp の読み取りと学習、計算、マスタ、品質データの写し、見えない Edge） | すでに 250 件余りの試験で固めてある処理。HTML の解析・データの照合は Python が得意で、書き直す利点より危うさが大きい |
| **画面**（WebView2） | これまでと同じ HTML/JS/CSS | 変えない。問い合わせは `fetch("/api/...")` のまま |

Rust に移したのは「窓とプロセスの世話」と「Python を通す必要の無い仕事」だけで、業務の処理（LotDsp・計算・マスタ）は移していない。段階 2・3 は §7・§8、Python の同梱（段階 4）は §9。

## 3. つなぎ方（ポートなし）

```
 WebView2（画面）
   │ fetch("/api/...")  … 置き場は http://tpa.localhost/（Windows）・tpa://localhost/（ほか）
   ▼
 Rust: 自前の仕組み "tpa" を受ける（desktop/src/router.rs）
   ├─ /static/…          → ディスクから直接（Python を通さない）
   ├─ /api/shutdown など → 窓が答える（終了・自己診断）
   └─ それ以外           → 中身へ渡す
                              │ 標準入出力の枠（desktop/src/frame.rs ⇄ program/sidecar.py）
                              ▼
                        Python: アプリ（app/web.py の App.handle）へそのまま渡す（版 3.8.0 で Flask を外した。§ Flask を外す）
```

- **枠**: ヘッダー JSON 1行（`len` が本文のバイト数）＋本文そのまま。base64 にしないので大きな一覧でも膨らまない。問い合わせに番号を付け、答えは番号で持ち主へ返す（長い問い合わせが短いものを待たせない。Python は 16 本の糸で答える）。
- **標準出力の保護**: アプリのどこかが `print` しても枠に混ざらないよう、sidecar は fd 1 を標準エラーへ向け直し、枠は複製した fd だけに書く。
- **終わり方**: 窓を閉じる → Rust が中身の入力を閉じる → Python が入力の終わりを見て自分で終わる（3 秒で終わらなければ止める）。Rust が強制終了されても OS がパイプを閉じるので、Python は残らない。ハートビートで推し量る必要が無い。
- **止まったら**: 中身が途中で止まると、待っている問い合わせへ 503（理由つき）を返し、次の問い合わせで起こし直す。送る前に止まっていた問い合わせだけ1度送り直す（送った後の問い合わせは二重に書かないよう送り直さない）。
- **1つだけ起動**: 2つめの exe は前の窓を前に出して終わる（tauri-plugin-single-instance）。ポートを見て止め直す仕組みが要らない。
- **外のリンク**: LotDsp を開く（`window.open`）・ページの外への移動は、いつものブラウザ（Edge）で開く（ログインと LotData-Link はそちらにある）。

## 4. 画面の設定の引き継ぎ

localStorage は置き場（オリジン）ごとに別なので、ブラウザ版（`127.0.0.1:57821`）とデスクトップ版（`tpa.localhost`）は互いの設定（列の並び・読み替えルール・プリセット・窓の配置など 25 項目）を見られない。
そこで、画面が覚え直すたびに **変わった名前だけ** をこの PC の作業場所の `ui_state.json` に重ね（`app/services/ui_state.py`・`/api/ui-state`）、開くときに控えの版（rev）が進んでいれば戻す（`shared.js` の `uiState`）。

- 控えを丸ごと置き換えない: 2つの窓が同時に開いているとき、片方の古い全体がもう片方の新しい変更を消さない（評価で1度この不具合を見つけて直した）。
- 一度も控えと揃えたことのない画面に設定があれば、それは前の版から使い込んだ設定。控えは足りない名前だけ補い、手元を優先して送る（先に開いたデスクトップ版の「まだ何も決めていない設定」で消さない）。
- 控えは画面の HTML に埋めて渡す（部品が設定を読む前に戻せる。読み直しが要らない）。
- 閉じる瞬間は sendBeacon で送るが、使えない WebView（Linux の WebKitGTK は `tpa://` 宛てで例外）では fetch で送る（評価で見つけて直した）。

## 5. ブラウザ版との関係（版 2.x まで。版 3.0.0 で外した）

- 同じ program フォルダを使う。違うのは入口と窓口だけ（`server.py`＝ポート、`sidecar.py`＝標準入出力）。起動して裏で始めること（品質データの写し・マスタの初期値）は `app/boot.py` の1箇所。
- **LotData-Link（Edge 拡張）はブラウザ版だけ**で動く（拡張は WebView2 の中には入らない）。デスクトップ版の LotDsp の読み方は、API（ログインなし）→ 見えない Edge → **LotDsp の窓**（ログインが要るとき。版 2.3.0・§10）→ 貼り付け。
- 移行の間は両方を配る。デスクトップ版で困らないことが確かめられたら、ブラウザ版の起動の仕組み（launch_guard・lifecycle・loading.html・stop.bat）を外せる（§10.3）。

## 7. 段階 2: 異常ロット一覧を Rust へ（版 2.1.0）

業務の処理を Rust へ移すのは、**同じ入力で同じ答えになることを試験で示せるときだけ**にする。その最初が異常ロット一覧の問い合わせ。

### 7.1 先に測った（3 万行 × 40 列・各 5 回の中央値・JSON にするまで）

| 操作 | Python v2.0.0 | Python 2.1.0 | Rust 2.1.0 |
|---|---|---|---|
| 1 ページ目（500 行） | 19ms | 25ms | 11ms |
| 検索「汚れ」（全 40 列） | 687ms | 657ms | **237ms** |
| 条件 2 つ（等しい・90 日以内） | 61ms | 76ms | 24ms |
| 並べ替え | 28ms | 28ms | 25ms |
| ロット番号でまとめる＋並べ替え | 1,981ms | 345ms | **220ms** |
| 数で絞る | 71ms | 69ms | 24ms |
| 0 件（日付の手がかり） | 467ms | 365ms | **109ms** |

遅さの元は2つだった（切り分けて測った）。

- **検索・0 件の手がかり**: SQL の中の CStr・ToDate を、行×列の回数だけ Python の関数として呼ぶ手間（検索 567ms のうち約 460ms）。
  → Rust では SQLite の中の Rust の関数になり、この手間が消える（2.8〜3.3 倍速）。
- **まとめる**: 関数の手間は 17ms ほどで、大半は SQL の作り（40 列すべてを窓関数の6段に持ち回す）。Rust にしても速くならない。
  → 並びを「行番号・並べ替えの順・ロットの見分け」だけで決め、そのページの行だけを後から読む形にした（`lot_list.grouped_sql`）。
  Python でも 5.7 倍速（1,981 → 345ms）。行番号の無い表（ビュー・WITHOUT ROWID）は前の形へ戻る。

試して入れなかったもの: 検索で文字・整数の列を CStr を通さずに比べる形（`CASE typeof(…)`）。Python は 1.5 倍速になったが、
Rust は 237 → 266ms と遅くなった（Rust の CStr はもともと速く、分岐を足す手間のほうが大きい）。デスクトップ版は Rust で引くので入れていない。

答えの大きさ（1 ページ・500 行）: Flask は日本語を `\uXXXX` で送るので 571KB、Rust は UTF-8 のままで 395KB。

### 7.2 分け方

- **Rust**（`desktop/src/lotlist.rs`）: 品質データ（SQLite）を引く。SQLite は exe に同梱（どの PC でも同じ版・窓関数が使える）。
  CStr・Val・ToDate・Nz を Rust で持ち、Python の str() と同じに値を文字にする（`desktop/src/pyfmt.rs`。2.73→"2.73"・1e16→"1e+16"・1.0→"1.0"・全角の数字など）。
- **Python**: どのファイルを読むか（品質データの写しの係 `db_mirror.py`）と、いつのデータか。Rust は一覧の問い合わせのたびに
  `/api/lotlist/plan` を尋ねる（読む場所・既定の表と件数・source・engine）。
- **戻し方**: 設定 `desktop.lotlist_engine` を `"python"` にすると、Rust は一覧を Python に任せる（食い違いに気づいたときの退避）。
  問い合わせに `engine=python` を付けると、その1回だけ Python が答える（自己診断の突き合わせに使う）。

## 8. 段階 3: 品質データの写しを Rust へ（版 2.2.0）

### 8.1 分け方

- **Rust**（`desktop/src/mirror.rs`）: 共有の元ファイルを手元へ写す係。`db_mirror.py` と同じ手順・同じ台帳（作業場所の `db_cache/_mirror.json`）・
  同じ世代名（`lot_list.g<世代>.sqlite3`）・同じ文言。起動の直後から裏の糸で写し始め、一定間隔で元の (パス, 大きさ, 更新時刻 ns) を見る。
- **Rust**（`desktop/src/lot.rs`）: `/api/lotlist`・`/api/lotlist/source`・`/api/lotlist/refresh`（再読込）に答える。
- **Python**: 一覧の設定（元ファイル・写す間隔・古さのしきい・既定の表と件数）だけを答える（`/api/lotlist/settings`。参照先マスタは共有のマスタにあるため）。
  Rust は設定を 10 秒覚え（`SETTINGS_TTL`）、参照先を保存したとき（`PUT /api/settings/lot_list.…`）はすぐ尋ね直して当て直す。
  ほかの PC が参照先を直したときは、遅くとも 10 秒で切り替わる（ブラウザ版は次の問い合わせで切り替わる）。
- **写しの係は1つだけ**: デスクトップ版で Rust が受け持つとき（`TPA_SHELL=desktop` かつ `desktop.lotlist_engine` が `"rust"`）、
  Python の写しの係は受け身（`DbMirror(passive=True)`）になり、写さず台帳を読むだけにする。`"python"` にすると、写しも一覧も Python に戻る。
- ブラウザ版とデスクトップ版を同じ PC で同時に開いても、同じ台帳を互いに読む（どちらかが写せば、もう一方は写し直さない）。
  Rust の一時ファイルの名前にはプロセス番号を入れ、Python の一時ファイルとぶつからないようにした。

### 8.3 速さ（参考）

写しを Rust にした利点は速さではなく、写しの係が1つ（Rust）にまとまり、起動の直後から写し始めること。一覧1回（1 行だけ）の問い合わせは、
3,000 行で Rust 2.1ms・Python 2.8ms、3 万行で Rust 5.1ms・Python 9.3ms（Linux の WebKitGTK）。どちらも画面の操作で分かる差ではない。

起動の直後から写し始めるのは前と同じだが、設定（元ファイルの場所）を Python に尋ねるので、Python の読み込み（約 1 秒）を待ってから始まる。
Python の起動を待たずに写し始めるには、参照先マスタの読み方も Rust へ移す必要がある（マスタの共有は移さないものに入れているので、今回はしない）。

### 8.4 次の候補

| 候補 | 利点 | 気をつけること |
|---|---|---|
| Python の同梱（embeddable） | 各 PC に Python と Flask を入れなくてよくなる | 配る物が大きくなる。社内の配り方と合わせて決める → **段階 4（§9）で行った** |

移さないもの: LotDsp の画面の解析・API の学習（`lotdsp_progress.py`・`lotdsp_api.py`）、計算（`calculator.py`）、マスタの共有（`master_store.py`）。試験で固めた業務の処理で、Python のままで遅くない。

## 9. 段階 4: Python を同梱する（版 2.3.0）

各 PC に Python と Flask を入れなくても動く「配る ZIP」を足した。Python を Rust に書き換えるのではなく、**Python の置き場所と版を配る側が決める**段階。
これまでは利用者の PC の Python に頼っていたため、次の揺れがあった: Python が無い・古い・Flask が無い／版が違う・別の Python の環境変数（PYTHONPATH）や site-packages が混ざる。

### 9.1 作り方（`desktop/bundle/bundle.py`）

| 何を | どうしたか | 理由 |
|---|---|---|
| Python の出どころ | NuGet の `python` パッケージ（Python Software Foundation が python.org のリリースと一緒に出す Windows 用の公式の実行環境・署名つき）。版 3.13.16 | 中身の指紋を手元でも NuGet の目録（SHA-512）と照らせる。python.org の embeddable ZIP は CI 以外から取りに行けないことがあった |
| 改ざん・取り違えを防ぐ | `runtime.json` に SHA-256 を固定し、違えば組み立てない。部品（Flask・Werkzeug・Jinja2・MarkupSafe・itsdangerous・click・blinker・waitress）は `requirements.txt` に版と指紋を固定（`pip install --require-hashes --no-deps`） | 同じ版を作り直しても同じ中身になる。版を上げるのは `bundle.py lock` だけ |
| 外と隔てる | embeddable と同じ形にする: 標準ライブラリを同梱の Python 自身で .pyc にして `python313.zip` へ、`python313._pth` で読み込み先を `zip・DLLs・Lib\site-packages・..\program` だけに決める（site は読まない） | 利用者の PC の PYTHONPATH・PYTHONHOME・ほかの Python の site-packages・sitecustomize を読まない。標準ライブラリが 1 つの zip なので、ファイルの数が減る（共有フォルダへ置き換えるとき、小さなファイルを数多く写さずに済む） |
| 入れないもの | pip・ensurepip・venv・IDLE・tkinter・試験・C の見出し | 隔てた形では使わない |
| アプリ | `git ls-files` の program・Start.vbs・README.md と exe | 手元の設定や .pyc を混ぜない |

隔てたことで、`PYTHON*` の環境変数が効かなくなる。.pyc の置き場（`PYTHONPYCACHEPREFIX`）は起動の入口ごとに引数 `-X pycache_prefix=<作業場所>\pycache` で渡すようにした（Start.vbs・start.bat・launch_guard・Rust の sidecar）。
評価で、以前のデスクトップ版が起動のたびに program フォルダへ `app_env` の .pyc を書いていたことも分かり、あわせて直った（引数は同梱でない Python にも効く）。

入口の Python の探し方は、どれも「隣の `python` フォルダ」を最初にした（Rust の `locate.rs` は 2.0.0 から、Start.vbs・start.bat・stop.bat はこの版から）。無ければこれまでどおり PC の Python を使うので、今までの配り方も使える。

### 9.2 評価関数（`desktop/bundle/verify.py`・Windows の CI で毎回）

利用者の PC を真似て、意地悪をしてから確かめる: PATH から Python のあるフォルダを外す、`PYTHONPATH`・`PYTHONHOME` を囮のフォルダへ向ける（囮の `flask` と `sitecustomize` は読まれたら失敗する）、作業場所はまっさら。

| 確かめ | 何を見るか |
|---|---|
| 中身がそろっている | 入口・exe・program・python・標準ライブラリの zip・部品 |
| 同梱の Python が自分の中だけを読む | 読み込み先がすべて配る形の中・isolated・囮を読まない・部品の版が組み立ての記録（BUNDLE.json）と同じ・SQLite と SSL・アプリが答える |
| デスクトップ版の自己診断 | exe を 2 回（まっさらな PC・2 回目以降）。全項目合格・中身の Python が同梱のもの・読み込みにかかった秒 |
| ~~ブラウザ版の起動~~ | Start.vbs と同じ起こし方（pythonw → start_app.py → launch_guard → server.py）。サーバーの Python が同梱のもの・終了を頼むと止まる（版 3.0.0 でブラウザ版とともに外した） |
| ~~Start.vbs の選び方~~ | デスクトップ版（exe）を開く（版 3.1.0 で Start.vbs とともに外した。代わりに更新の通し: §11.4） |
| Python の試験 | program の試験すべてを同梱の Python（3.13）で。CI のふだんの試験（3.12）と合わせて 2 つの版で確かめる |
| program・python に .pyc を書かない | 上の確かめのあと、配る形の中に `__pycache__`・`.pyc` が無い |
| 終わったあと残らない | 配る形の exe・Python のプロセスが残っていない |

Windows の CI で測った値（2026-10-02・GitHub の windows-latest）:

| 何を | 値 |
|---|---|
| 大きさ | 展開した形 35.6 MB・360 ファイル（うち python 25.6 MB・252 ファイル）・配る ZIP 16.7 MB |
| 同梱の Python | 3.13.16・SQLite 3.50.4・OpenSSL 3.5.9・標準ライブラリの zip 533 ファイル・MarkupSafe の速い版が効く |
| デスクトップ版 | 自己診断 25 項目合格 × 2 回。Python の読み込み 0.23 秒（まっさらな作業場所）・0.14 秒（2 回目） |
| ブラウザ版 | 同梱の pythonw で準備まで 3.3 秒 |
| 試験 | program の 267 件が同梱の 3.13 で合格（133 秒） |

評価で見つけて直したこと: 評価関数自身が `program/app_env.py` を読むときに .pyc（`cpython-312`）を書き、「.pyc を書かない」を不合格にしていた
（同梱の 3.13 なら `cpython-313`。版の違いで、書いたのがアプリでないと分かった）。読むあいだは .pyc を書かないようにした。

評価関数そのものも試験した（`desktop/bundle/test_bundle.py`）: 同梱でない Python を当てると、起動できない（囮の PYTHONHOME）・読み込み先が外・囮の flask を読む・部品の版が違う・アプリが答えない、をそれぞれ不合格にする。
手元の Flask が偶然同じ版（3.1.3）だったため、版の食い違いを見落とす試験になっていたのを、ありえない版にして直した。

### 9.3 分からないこと

- 社内の PC で、展開した `python` フォルダの exe・`TransferPitchAnalyzer.exe` が止められないか（AppLocker などで、利用者のフォルダの exe を禁じていないか）。**分からない**。python.exe は Python Software Foundation の署名つき、TransferPitchAnalyzer.exe は署名なし。
- インターネットから取った ZIP を展開すると、Windows がファイルに「インターネットから来た」印を付け、Start.vbs を開くときに警告が出ることがある。社内の置き場から配るときに出るかは **分からない**（出るなら、ZIP のプロパティで「許可する」を付けてから展開する）。

## 10. 段階 5: デスクトップ版へ一本化する（版 2.3.0 から）

## 11. 段階 6: exe 起動へ一本化し、更新の仕組みを足す（版 3.1.0）

利用者が「社内の PC で、署名の無い exe が止められない」と確かめた（2026-10-04）。入口を exe だけにし（Start.vbs を外す）、
配り直し（新しい版への入れ替え）を各 PC の手作業にしない仕組みを足した。

### 11.1 決めたこと（と、選ばなかった道）

| 問い | 決めたこと | 選ばなかった道と、その理由 |
|---|---|---|
| どこから新しい版を取るか | 参照先の「更新の置き場」（`update.source`。共有のマスタなので 1 台で決めれば全員に効く）に置いた配る ZIP | GitHub の Releases を直接: 社内の PC から届くか**分からない**・認証情報を持たせない決まり |
| どこへ入れるか | この PC の作業場所の `versions\<版>\`（版ごとのフォルダ） | 配ったフォルダを置き換える: 動いている exe・Python は「使用中」で入れ替えられない。共有フォルダから大勢が開いていると、1 人の入れ替えがほかの人を止める・途中で壊す。書けない場所に置いてあると更新できない |
| どう新しい版で開くか | 配った exe が起動の最初（窓を作る前）に、自分より新しい版が入っていればその exe を起こして終わる（引き継ぎ） | 小さな起動用の exe を別に作る: 入口が 2 つになり、それ自体の更新が要る |
| 壊れた版が来たら | 取り込む前に指紋（`.sha256`）と中身を確かめる。起動できなければ印（`FAILED.json`）を付け、次から前の版で開く | 確かめずに入れる: 置き場への書き込みの途中・壊れた ZIP で全員が開けなくなる |

ショートカット・タスクバーのピン留めは、配った exe を指したままでよい（いつでも最新の版へ引き継ぐ）。

### 11.2 流れ（`desktop/src/update.rs`）

1. **確かめる**（起動の直後・30 分ごと・参照先で置き場を保存したとき）: 置き場に `TransferPitchAnalyzer-X.Y.Z-windows.zip` があり、いまの版と取り込み済みの版（起動できなかった版も）より新しいか。版は数で比べる（3.10.0 は 3.9.0 より新しい）。いまの版は `program/app/version.py` から読む（exe の版と食い違っても、配る物の名前と同じ所で比べる）。
2. **取り込む**: 手元へ写す → 隣に `.sha256` があれば指紋を照らす → `versions\.staging-…` に展開（絶対パス・ドライブ名・`..` の名前があれば断る。1 GB を超えれば断る）→ 中身を確かめる（exe・`program\sidecar.py`・`python\BUNDLE.json` があり、名前・`version.py`・`BUNDLE.json` の版がそろう）→ `READY.json` を書いて `versions\X.Y.Z` へ名前を変える（一度に入れ替わる。途中で止まっても半端な版を選ばない）。
3. **引き継ぐ**: 起動の最初に、`READY.json` があり `FAILED.json` の無い、自分より新しい版のうちいちばん新しい exe を起こして終わる。同じ版・古い版へは引き継がない（繰り返さない）。開発（`TPA_PROGRAM_DIR`）と `--no-handoff` では引き継がない。
4. **更新して開き直す**: 画面の「更新して開き直す」→ 窓が新しい版の exe を `--after-update` で起こしてから閉じる。新しい版は、前の窓が閉じる（作業場所の `run.lock` の錠が外れる）まで最大 30 秒待ってから窓を出す（1 つだけ起動の仕組みに前の窓と見なされないように）。
5. **片付ける**: 新しい版で開いたら、それより古い版のフォルダを消す。先に名前を変えてから消すので、使用中なら丸ごと残る（次の機会に）。
6. **起動できなかったら**: 更新で入った版で Python が見つからない・中身が起動できないときは、その版に `FAILED.json` を付け、起動画面で「次から前の版で開く」と言う。

画面: 版の札の横の札は 1 つにまとめた（取り込み済みなら「更新あり X」＝緑、ほかの人がもっと新しい版を使っているだけなら「新しい版あり」）。押すと更新履歴の窓の上に、版のこと（取り込んだ版・取り込めない理由と置き場・起動できなかった版）と次にすること（「更新して開き直す」）が出る。

### 11.3 置き場への置き方（配る人）

GitHub の Releases から `TransferPitchAnalyzer-<版>-windows.zip` と `.sha256` を取り、更新の置き場へ入れる（`.sha256` を先に・ZIP を後に置くと、書き込みの途中の ZIP を指紋で断る）。古い版の ZIP は消してよい（取り込むのはいちばん新しい版だけ）。

### 11.4 評価関数

- Rust の試験（`update.rs`・9 件）: 版の比べ（数で比べる・形の違う名前を断る）・`version.py` を読む・置き場からいちばん新しい ZIP を選ぶ（書き込み途中の名前・フォルダを見ない）・取り込み → 引き継ぎ先（同じ版・古い版へは引き継がない）・断る 7 通り（中身の版が違う・BUNDLE の版が違う・`..`・絶対パス・ZIP でない・指紋が違う・指紋の形が違う）でどれも何も残さず外にも書かない・起動できなかった版を飛ばして取り込み直さない・係の状態（off・error・latest・ready・パスのコピーの `"`）・片付け（古い版と名残だけ）・動いている印の錠（2 つめは取れない・閉じれば待っていた側が取れる）。
- 配る形の確かめ（`verify.py` の update・Windows の CI）: 版を 1 つ上げた配る ZIP と指紋を置き場に置き、本物の exe で 4 回起こす。① 取り込む（自己診断の「更新の係」が ready）② 開き直すと新しい版の program・Python で動く ③ 新しい版を壊すと起動に失敗し `FAILED.json` が付く ④ 次は前の版で開き、起動できなかった版を伝える。配ったフォルダのファイルが 1 つも変わっていないこと、終わったあと取り込んだ版が残っていないことも。
- 手元（Linux の WebKitGTK）でも同じ 4 段を本物の窓で通した。「更新して開き直す」の待ち合わせ（前の窓が開いている間は新しい窓が待ち、閉じたら開く）も確かめた。
- 画面の評価 17 項目（窓の更新の係を作り物に差し替え、Playwright）: 確かめ中は札を出さない・「更新あり」と色・更新履歴の窓の次にすること・枠に収まる・apply を頼む・取り込めない理由と置き場・起動できなかった版・最新なら出さない・置き場を保存したらその場で確かめる・参照先のカードと「確かめる」。

## 14. 段階 9: アプリの配布（版 3.4.0・WaveLog の良い所を移す）

利用者の決めたこと（2026-10-04）: 配布の仕組みは WaveLog（別リポジトリ）がよくできているので、良い所を移す。選んだのは 4 つ:
① 配る版を選ぶ（いちばん新しい版ではなく、選んだ版にそろえる・戻すのも選び直し）② 画面から版を置く ③ アドレスだけで新しい PC へ ④ 実行前の警告を出さない。
TransferPitchAnalyzer の良い所（版ごとに並べて置く・起動できない版は前の版で開く・BOX の見え方の違いを付け直す・app_id で見分ける）はそのまま残す。

| WaveLog | TransferPitchAnalyzer（版 3.4.0） | 違えた理由 |
|---|---|---|
| `release.json`＝配る版、`versions/<版>/manifest.json`＝ファイルごとの指紋 | `distribute.json`＝配る版、`<版>/release.json`＝ZIP の指紋（§12.1 の形のまま） | 版 3.2.0 から置き場の形が決まっている。`release.json` の名前を変えると 3.3.0 までの PC が版を見つけられない |
| Python（Flask）が ZIP を検めて置く | 窓（Rust・`desktop/src/distribute.rs`）が置く。だれが置いてよいかは Python（`services/access.py`）に尋ねる | 置き場の探し方（BOX の見え方）と取り込みの確かめ方が Rust にある。同じ確かめ方（`update::extract`・`validate`）を置くときにも使う |
| 入れ替える（アプリのフォルダの項目を差し替え・失敗したら戻す） | 版ごとに並べて置き、引き継ぐ（§11） | 動いている exe・Python を置き換えない。起動できない版は前の版で開ける |
| 入口の exe はこの PC へ自分を写してから入れる | 配る入口は起動画面だけを出し、配る版を取り込んで起こす（自分は写さない） | 取り込みは数十秒で終わり、終われば入口は閉じる。入口を開いている最中に配る版を選び直すと入口を置き換えられないので、理由を言って押し直してもらう |
| 新しい PC へ共有のマスタの置き場を渡す（`install.json`） | 渡さない（マスタの共有フォルダは配った設定に入っている）。入口の置き場だけ控える（`entry.json`） | 設定は配る形に入っていて PC ごとに書かない |

### 14.1 配る版（`desktop/src/release.rs`・`update.rs`）

- アプリのフォルダに `distribute.json` `{schema:1, app_id, version, entry, setAt, setBy, setPc, previous}`。置き場を探すとき `release.json` と一緒に集め、
  このアプリの物（app_id）のうち、あとで決めた物が効く（アプリ名を変えて新しいフォルダで配ったときも、新しい方）。点で始まるフォルダ（置いている途中）は見ない。
- 更新の係は、配る版があればその版がこの PC に無いとき取り込み、作業場所の `want.json` に覚える。引き継ぎは「覚えた版」へ（古くても＝前の版へ戻す）。
  まだ取り込めていない（BOX の同期待ち）・この PC で起動できなかった配る版へは移らない。配る版が無い置き場では `want.json` を消し、いちばん新しい版へ（版 3.3.0 までの決まり）。
- 片付けは、覚えた版があれば「いまの版と覚えた版のほか全部」、無ければ「いまの版より古い版」。この PC に入れた app は、覚えた版で動いたときにその版へ入れ替える（前の版へ戻したときも）。
- Python の利用状況は `want.json` を読み、配る版を「最新版」にする。配る版と違う版（戻したときは新しすぎる版も）を「要更新」にする。

### 14.2 画面から版を置く・配る版を選ぶ（`desktop/src/distribute.rs`・画面は `master.js` の「アプリの配布」）

- 置く: 画面が ZIP を**読み終えたバイト列**で送る（ファイルのまま送ると、Linux の WebKitGTK は本文を読む所で落ちた。Windows の WebView2 でもバイト列なら同じに動く）。
  窓は作業場所に書き、展開して確かめ（このアプリの app_id・版・exe・同梱の Python）、置き場の `.<版>.placing-<pid>` へ ZIP を写して指紋を確かめ直し、`release.json` を書いてから名前を変える。
  同じ版はもう置かない（取り込んだ PC と中身が食い違う）。進み具合（確かめる→写す n/N バイト→仕上げ）を画面が問い合わせて描く。1 台で同時に置けるのは 1 本。
- 配る: `distribute.json` を書き、配る入口（その版の ZIP の exe。指紋を確かめた ZIP からだけ）をアプリのフォルダの直下に置く。入口の名前が変わった版を配ったら前の名前の入口を消す。
- 置く・配るのは開発者・メンテナンス者だけ（`role_can(…, "release:publish")`）。窓は `/api/update/settings` の `who.canRelease` に従い、切断中の PC は置けない。

### 14.3 アドレスだけで新しい PC へ・実行前の警告

- exe は起動のはじめに、隣に自分の名前を入口とする `distribute.json` があれば「配る入口」として動く: 起動画面に段（配る版を確かめる → この PC へ写す → 開く）を出し、
  配る版を取り込んで `want.json` に覚え、入口の置き場を `entry.json` に控えてから、その版を起こして閉じる（中身の Python は起こさない・1 つだけ起動の決まりも持たない）。
  開いた版は配ったフォルダから開いたのと同じなので「この PC に入れますか」と尋ねる（版 3.5.0 からは、取り込んだ版を app へ写してから開く。§15）。控えた置き場は、参照先の更新の置き場の後ろの候補になる（その PC で参照先の置き場が見えなくても届く）。
- アプリが写したファイル（この PC に入れるときに配る形から写す物）からは `Zone.Identifier`（インターネットから来た印）を外す。Windows の写し方は別の流れも写すので、
  エクスプローラーで展開した ZIP から入れると、入れた exe を開くたびに実行前の警告が出ていた（WaveLog で利用者が報告したのと同じ）。取り込み・入口は Rust が ZIP から書くので印は付かない。

### 14.4 評価関数

- Rust（`cargo test`）: 置いた版が各 PC の取り込みにそのまま通る・途中の物を残さない・同じ版を断る・ほかのアプリや名乗りの無い ZIP を断る／配る版と入口・戻す・前の版の控え・画面の答え／

### 15.2 改めた所（`desktop/src/install.rs`・`main.rs`）

- **写すのは尋ねない**（`localize`）: exe は起動のはじめに、自分の配る形が作業場所の外（共有・BOX・自分で展開したフォルダ）なら、`app` が使える（写してある・入れ替える決まり `should_replace` に当たらない）とき
  はその exe を起こして終わる（窓を出さない・すぐ）。使えなければ起動画面に段（この PC へ写す → 開く）を出して `app` へ写し、そちらを起こす。
  写し方は版 3.2.0 と同じ（`.app-new-…` へ写す → 入れ替える。途中で止まっても `app` は丸ごと前か後・`.pyc` は写さない・インターネットの印は外す）。

- 窓の答え: `GET /__desktop/install`（`installed`・`runningFromApp`・`local`・`shortcut{links, places, ask, declined}`）・`POST /__desktop/shortcut`・`POST /__desktop/shortcut/decline`。
  版 3.4.0 の `POST /__desktop/install`・`/__desktop/install/relaunch` は外した（写すのは起動のはじめに済んでいる）。
- 更新（§11・§14）はそのまま: ショートカット → `app` の exe → 覚えた版（`versions/<版>`）へ引き継ぐ → その版が `app` を入れ替える → 次からはショートカットでその版が開く。

### 段 B: 異常ロット一覧を Rust へ（版 3.9.0・同じ PR）

§7・§8 の作り（`lotlist.rs`・`pyfmt.rs`・`mirror.rs`・`lot.rs`）を作り直した。Rust の処理は窓に依らない部品（`desktop/src/lib.rs`＝`da_core`）に分け、

- **Python と同じ書き方**（`pyfmt.rs`）: 小数は Python の repr（-4〜16 桁の外は指数）、バイナリは bytes の repr、数字と空白は Python の
  正規表現と同じ Unicode の決まり（`\d`・`isspace` の範囲表は Python の unicodedata から作った）、日付は Python と同じ順に試し最初に形が合った読み方で決める。

## 段 C1: この PC へ写す・更新（版 3.10.0・方式 B+）

利用者の決めたこと（2026-10-05〜06）:
- Python は各ユーザーが PC に入れる（同梱しない）。**Microsoft Store 版でも動くように配慮する**。
- 更新は B（WaveLog の形: この PC へ写し、ショートカットから写しで開く・起動の最初に入れ替える）に、A の良い所 2 つを足した **B+**。
  比べた案と点数（55 点満点・重みつき）: A 版ごとに並べて引き継ぐ 42・B WaveLog そのまま 38・**B+ 46**・C 共有から直接 25・D 起動専用の exe 34・E Windows の導入の仕組み（使えるか分からない）。

### 形（この PC の作業場所 `%LOCALAPPDATA%\TransferPitchAnalyzer`）

| 置き場 | 中身 |
|---|---|
| `app\` | この PC のアプリ（exe・program・README）。入口はここの exe |
| `desktop\<大きさ-更新時刻>\<exe>` | 版ごとに写した exe。窓として動くのはこちら（動いている窓が app を掴まない） |
| `update\stage\`・`stage.json` | 使っている間に裏で取り込み、確かめ終えた次の版 |
| `update\old\` | 直前の版の控え |
| `update\applied.json`・`FAILED.json` | 入れ替えた直後の印（起動できたら消す）・起動できなかった版 |
| `want.json` | 配る版（Python の利用状況が「最新版」に使う） |

作業場所を AppData の外へ出した WaveLog と違い、AppData のままにした: WaveLog は「Python が書いて窓が読む」ファイルがあり、Store 版の Python の書き込みの付け替えで
窓から見えなかった。Defect-Analyzer は窓と Python のやり取りをパイプで行い、ファイルは「窓が書いて Python が読む」向きだけ（読むときは本当の場所も見える）。

### 流れ（`desktop/src/update.rs`・`updater.rs`・`main.rs` の `hand_off`）

1. 起動のはじめ（窓を作る前・`update::plan`）: 共有・BOX・展開したフォルダの exe なら、この PC の app へ写す（app が無い・この配る形の方が新しいときだけ。
   `.pyc` は写さない・exe の「インターネットから来た」印を外す）→ app の exe を開いて終わる。app の exe（入口）なら版ごとの写しへ渡して終わる。
   開発の作業ツリー（program の隣に .git）・`--here`・`TPA_NO_HANDOFF` はそのまま動く。
2. 窓（Python を起こす前）: 取り込み済みの版があれば app を入れ替える（app → old、stage → app。使用中は 3 秒まで待つ・失敗したら戻す）。exe も変わったら入口で開き直す。
3. 中身（Python）が起動できなければ、入れ替えた直後の版に印を付け、控えへ戻して開き直す。起動できたら印を消し、古い版ごとの写しを片付ける。
4. 使っている間（起動の直後・30 分ごと・画面の「確かめる」・更新の置き場の保存）: 置き場を Python に尋ね（`/api/update/settings`）、BOX の見え方を付け直して探し（`release.rs`）、
   配る版があればその版（前の版へ戻すときも）、無ければいちばん新しい版を取り込む: 写す → 指紋（SHA-256）→ 展開（危ない名前・1 GB 超を断る）→ 中身（exe・program・app_id・版）→ stage。
5. 「更新して開き直す」（`/__desktop/update/apply`）: 入口を `--wait-pid` で起こして窓を閉じる。入口は前の窓が終わるのを待ってから渡す（1 つだけ起動の仕組みに前の窓と見なされない）。
