# Defect-Analyzer（転写距離・ピッチ解析）

Windows のアプリ（`Defect-Analyzer.exe`）です。入口はこの exe 1つです（版 3.0.0 でブラウザ版を、版 3.1.0 で Start.vbs を外しました）。新しい PC には BOX の置き場の**配る入口のアドレス**を渡し、ダブルクリックするだけで使い始められます（起動に要る物はアプリがこの PC へ写し、以後は共有・BOX につながっていなくても開きます）。以後はデスクトップ・スタートのショートカットから開き、配る人が決めた版（配る版）に各 PC がそろいます（[はじめて使う](#はじめて使うこの-pc-へ写す)・[更新のしかた](#更新のしかた新しい版に入れ替える)）。

## 配り方（フォルダの形）

GitHub の Releases に、版ごとに配る ZIP（`Defect-Analyzer-<版>-windows.zip`）・`release.json`（更新の置き場に一緒に置く説明書き）・指紋（`.sha256`）が自動で置かれます（main に入って、Windows で作って確かめたあと）。ZIP を展開すると次の形になります。

```
転写計算\                    ← 展開したフォルダ（名前は自由）
  Defect-Analyzer.exe        ← 入口（これをダブルクリック。ショートカットもこれへ）
  README.md                  ← この説明
  program\                   ← アプリの中身（触らない）
  python\                    ← 同梱の Python 3.13（触らない）
```

- **各 PC に Python を入れる必要はありません。** 同梱の Python は Python Software Foundation の公式の Windows 用実行環境（NuGet の python パッケージ）から作り、版と指紋を固定しています。アプリは版 3.8.0 から Python の標準の部品だけで動きます（Flask などの部品は使いません）。PC に別の版の Python や部品・環境変数（PYTHONPATH など）があっても、同梱のものだけで動きます。作るたびに、利用者の PC を真似た確かめ（PATH に Python なし）を通してから置きます（[desktop/bundle](desktop/bundle)）。
- `program` の中身: `app`（画面と API）・`sidecar.py`（窓とのつなぎ）・`config`（設定）・`data`（マスタの初期値）・`docs`（仕組みの説明）・`tests`。
- 利用者ごとの記録やマスタの写し・この PC へ写したアプリ（`app`）・取り込んだ新しい版（`versions`）は `%LOCALAPPDATA%\TransferPitchAnalyzer` にあります。展開したフォルダは BOX・共有フォルダに置いて構いません（アプリはそこへ書き込みません）。
- 開発で Git を使うときの `.git`・`.gitignore` は配る物に入れません。

## はじめて使う（この PC へ写す）

1. 配る人から渡された**配る入口のアドレス**（例 `C:\boxdrive\Box\(D)_仕上課\90_アプリ開発\90_Releases\TransferPitchAnalyzer\Defect-Analyzer.exe`。BOX の見え方が違う人は `C:\boxdrive\Box\90_アプリ開発\…` のように自分に見える場所）をダブルクリックします。起動に要る物（exe・アプリの中身・同梱の Python）がすべてこの PC の `%LOCALAPPDATA%\TransferPitchAnalyzer\app` へ写って、そちらで開きます（初めてのときだけ数十秒。尋ねません。ZIP の展開も要りません）。共有・BOX に展開したフォルダの `Defect-Analyzer.exe` からでも同じです。
2. 「**ショートカットを作りますか**」と出たら「**作る**」を押します。デスクトップとスタートに「**Defect-Analyzer**」ができます（スタートの検索で「Defect」と打つと出ます。乗せると「転写距離・ピッチ解析」と出ます）。ショートカットはこの PC へ写した exe を指し、作業フォルダもこの PC です（共有を作業フォルダにしません）。タスクバーに置きたいときは、開いた窓のアイコンを右クリックして「タスクバーにピン留め」を押してください。
3. 以後は、そのショートカットから開きます。**共有・BOX につながっていなくても開け**、共有から直接開くより速く開きます。共有の exe（や前に作った共有を指すショートカット）を開いても、写さずにすぐこの PC の物が開きます。

- 「今回は作らない」（次の起動でまた尋ねる）・「今後たずねない」（この PC に覚え、次からは尋ねない）も選べます。あとから作るときは、版の札（`VER…`）を押した更新履歴の窓の「ショートカットを作る」から。ショートカットを全部消すと、次の起動でまた尋ねます（「今後たずねない」にしていなければ）。
- 起動のたびにショートカットを確かめ、共有の exe を指す物・作業フォルダが共有の物・前の名前（版 3.2.0 の「転写距離・ピッチ解析」など）の物は、この PC の exe で自動で作り直します。
- この PC へ写したアプリは、新しい版で開いたときにその版へ入れ替わります。ショートカットはそのままで、いつも新しい版が開きます。
- この PC へ写せないとき（作業場所に書けないなど）は、共有の物のまま開き、理由を更新履歴の窓に出します。
- **起動は exe（のショートカット）から**が推奨です。VBScript（.vbs）は Windows で廃止が予定されていて、対策ソフトにも止められやすく、タスクバーにも置けないため、使いません（版 3.1.0 で Start.vbs を外しました）。

## 起動・終了

デスクトップかスタートの「Defect-Analyzer」（ショートカットを作る前は `Defect-Analyzer.exe`）をダブルクリックします。起動画面で「Python を探す → アプリの中身を読み込む」を確かめてから、アプリの窓に切り替わります。起動できないときは、起動画面に理由と次にすることが出ます。

- **ポートを使いません**。プロキシ設定でアプリが答えなくなる・前の版が残って版が混ざる・ほかのプログラムとポートを取り合う、が起きません。
- 窓を閉じるか、画面右上の「終了」を押すと、中身（Python）も一緒に終わります。2回開くと前の窓が前に出ます。
- LotDsp を開くボタン・外のリンクは、いつものブラウザ（Edge）で開きます。
- 画面の設定（列の並び・読み替えルール・プリセット・窓の配置など）はこの PC に覚えます。以前のブラウザ版で使い込んだ設定も引き継ぎます。
- 異常ロット一覧は Rust が受け持ちます（問い合わせ・品質データの写し）。設定 `desktop.lotlist_engine` を `"python"` にすると Python で引くように戻せます。
- 記録はこの PC の作業場所の `logs\app.log`・`logs\sidecar_stderr.log` にあります。

## 更新のしかた（新しい版に入れ替える）

**置き場**: BOX の `C:\boxdrive\Box\(D)_仕上課\90_アプリ開発\90_Releases`（配った設定に入れてあるので、各 PC で設定しなくて構いません）。BOX の権限によって `C:\boxdrive\Box\90_アプリ開発\90_Releases` のように上の階層が見えない人でも、その PC で見える場所を探し直します。変えるときは「マスタ管理」→「参照先」の「更新の置き場」で（全員の PC に効きます。「確かめる」で、その PC で見つけた場所・配る版が分かります。「;」で区切って候補を複数書けます）。
**置き場の場所・フォルダの名前を変える**ときは、「マスタ管理」→「アプリの配布」の「**置き場を変える…**」で、置く場所（上のフォルダ）とフォルダの名前を入れます（打つたびに、使える名前か・写す量・使えない理由と、変えたあとのフォルダの形を木で出します: いまの置き場＝灰（残す）・新しい置き場＝藍（写す）と、その中の版・配る版）。「変える」で、いまの置き場の中身（置いた版・配る版・配る入口）を新しい場所へ丸ごと写し（写し終えてから名前を付けるので、各 PC が写しかけを読むことはありません）、参照先の「更新の置き場」を新しい場所に書き換えます（全員の PC が次に確かめたときから新しい置き場を見ます）。前の置き場は消さずに残すので、全員がそろったあとで要らなければ手で消してください。新しい場所が既に置き場なら写さずに切り替えるだけ、写さずに空の場所へ切り替えることもできます。変えられるのは、版を置ける人（開発者・メンテナンス者）で参照先を書ける PC だけです。新しい PC へ渡すアドレスも変わるので、「アドレスをコピー」で写し直してください。

**新しい版を配るとき（配る人＝開発者・メンテナンス者）**: 「マスタ管理」→「**アプリの配布**」で、① → ② の順に進めます（版 3.4.0〜・WaveLog と同じ流れ）。

1. **① 版を置く**: GitHub の Releases から `Defect-Analyzer-<版>-windows.zip` を取り、「**ZIP から版を置く…**」で選びます。アプリが中身（このアプリの物か・版・exe・同梱の Python）を確かめてから、置き場に版のフォルダと `release.json` を作ります（進み具合が出ます。同じ版はもう一度置けません）。**置いただけでは配りません**。
2. **② 配る版を選ぶ**: 試してから、一覧の「**この版を配る**」を押します。各 PC は起動したとき・30 分ごとに配る版を確かめて取り込み、開き直したときにその版になります。
3. **前の版へ戻す**: 一覧の「**この版に戻す**」を押すだけです（各 PC も前の版を取り込み、開き直したときに戻ります）。
4. **新しい PC へ**: 「アプリの配布」の「新しい PC へ」に出る配る入口のアドレスを「アドレスをコピー」で写して渡します（[はじめて使う](#はじめて使うこの-pc-に入れる)）。

```
90_Releases\
  TransferPitchAnalyzer\         ← アプリのフォルダ（名前は自由。アプリ名が変わっても構いません）
    distribute.json              ← 配る版（「この版を配る」で書く）
    Defect-Analyzer.exe          ← 配る入口（配る版の exe。新しい PC へはこのアドレスを渡す）
    3.6.0\                       ← 版のフォルダ（「ZIP から版を置く」で作る）
      release.json               ← このアプリの版だという印・版・ZIP の名前・指紋・exe の名前・置いた人
      Defect-Analyzer-3.6.0-windows.zip
```

アプリは置き場の下をたどって、このアプリの `release.json`・`distribute.json`（中の目印 `app_id`）を探すので、アプリ名・exe 名・フォルダ名が変わっても取り込めます。手で版のフォルダを作って `release.json` と ZIP を入れても構いません（GitHub の Releases に両方あります）。BOX への書き込み・同期が終わる前の ZIP は、指紋が合わないので取り込みません。

- **配る版が決まっていない置き場**（`distribute.json` が無い）では、これまでどおり各 PC がいちばん新しい版を取り込みます。
- **版 3.3.0 までの PC** は配る版を知らず、置き場のいちばん新しい版を取り込みます。3.4.0 を配って各 PC が 3.4.0 になるまでは、試しの新しい版を置くと配られることに注意してください。

**使う人**: 何もしなくて構いません。

1. アプリが起動の直後と 30 分ごとに置き場を確かめ、配る版がこの PC に無ければ作業場所（`%LOCALAPPDATA%\TransferPitchAnalyzer\versions`）へ取り込みます。そのあいだも今の版で使えます。
2. 取り込むと、見出しの版の札の横に緑の「**更新あり 〈版〉**」（戻すときは「**配る版 〈版〉 に戻す**」）が出ます。押して「更新して開き直す」を押すと、その版で開き直します。
3. 押さなくても、次にショートカットから開いたときにその版で開きます。この PC へ写したアプリもその版に入れ替わります。

- 取り込む前に、指紋（`release.json` の `sha256`）と中身（exe・アプリの中身・同梱の Python がどれもその版を名乗るか）を確かめ、合わない ZIP は取り込みません。理由は更新履歴の窓（版の札を押す）に出ます。
- 配る版が起動できなかったときは、その版を使わず今の版のまま開きます（更新履歴の窓に出ます）。要らない版は片付けます。
- アプリが写した exe・ファイルからは「インターネットから来た」印を外すので、更新のたびに Windows の実行前の警告が出ることはありません。
- 配ったフォルダ（BOX でも）は書き換えないので、ほかの人が使っていても止めません。
- 「マスタ管理」→「利用状況」の「最新版」は配る版になり、配る版と違う版の PC に「要更新」が付きます。

動いているあいだに `program` を入れ替えて画面が混ざったときは「アプリの版が混ざっています」と出るので、「アプリを再起動する」を押して開き直してください。

仕組み・役割の分け方・確かめ方は [program/docs/DESKTOP_MIGRATION_DESIGN.md](program/docs/DESKTOP_MIGRATION_DESIGN.md) にあります。

## 画面構成

解析画面は「入力＋転写計算」「入力＋ピッチ計算」の2パターンのみで、どちらも作業実績の入力列と計算結果列を同じ画面に表示します（タブ切替は2つだけ）。表示する列は各タブの「列表示」から個別に増減できます。

- **列の並び替え**: 「列表示」の窓で、つまみ（⋮⋮）のドラッグか ▲▼ で並べ替えられます。表の見出しをドラッグしても並べ替えられます。並べ替えは同じまとまり（基礎情報・作業実績入力・…）の中だけで、No.・設備は左に固定です。並びはこの PC に覚え、「並びを元に戻す」で戻せます。
- **巻取方向**: 表の「巻取 方向」（入力＋転写計算）で工程ごとに直せます。空欄（自動）なら設備マスタの値を「自動」の印つきで出し、上・下・- を選ぶとその値で面の反転と 3D のコイルの向きを計算します。「自動」を選ぶと設備マスタの値に戻ります。

- 汚れ位置 A・B は未入力から始まります。**計算に使うのは A だけ**です。A を入れると、発見設備から上流へさかのぼって各設備での混入位置（内側から何 m・肉厚何 mm）と 1 周の長さを求め、各設備を発生設備としたときに発見設備で何 m のラップ長さになるか（転写距離）を出します。B を入れると実測 |B−A| と比べ、誤差（既定 5%）内で一致した工程は行全体が緑になります。
- さかのぼりの板厚の比は、**1 つ下流の工程の板厚 ÷ その工程の板厚**です（体積が保たれるので、同じ汚れの「全長に対する位置の割合」がどの工程でもほぼ同じになる）。以前の式（発見板厚 ÷ その工程の板厚）は板厚が 2 回以上変わると上流ほど位置が内側へずれていました（見本 L6183D0 の HOT で全長の 0.4 %）。移植元と突き合わせるときは `calculation.trace_ratio` を `"found"` にすると以前の式で計算します。
- **エンドバック（後オフ）の自動計算**: 冷延設備（L-1・L-2・L-3 など、`calculation.end_back_equipment` 既定 `["L-"]`）で前工程より重量が減っていたら、減った重量（両エッジを落とした分は除く）から後オフの長さを求め、「総オフ後」の欄に自動で入れます（青緑の斜体と「自動」の印）。手で入れるとその値を使い、消すと自動に戻ります。
- **内径**: 表の「内径」（入力＋転写計算）で工程ごとに直せます。空欄なら設備ごとの既定（HOT は 610 mm・ほかは 558 mm。`calculation.hot_inner_diameter_mm`・`default_inner_diameter_mm`・設備ごとの `equipment_inner_diameter_mm`）を「自動」の印つきで入れ、手で入れるとその値、消すと自動に戻ります（以前の解析条件の「検入時内径」は計算に使っていなかったため、なくしました）。
- **作業日・比重は取り込んだ値**: 作業日は LotDsp の実績の日付で、表では直しません。比重は LotDsp の「比重」を基本情報に出して計算に使います（入力欄はありません）。ロットに比重が無いときは `calculation.default_density`（既定 2.7）を「既定」の印つきで使います。
- 最終工程が KEN のときは、それ以降の空き行を畳みます（「開く」で出せます）。
- 表の下の「計算の考え方」は、表の計算を 3D でたどり直します。
  - **入力＋転写計算**: 既定は**最も確からしい設備**（一致率が最も高い）を仮の発生設備とし、「発見位置 A からすると、この設備ではこの肉厚で混入していたはず → 1 周は ＊ m → 下流では巻き替えのたびに頭と尾が入れ替わり、前後のオフ・両エッジが落とされながら → 発見設備ではラップ長さが ＊ m になるはず」を描きます。コイルの 1 周の矢印は仮の発生設備だけで、以降の設備（圧延・巻き替えで「1 周」の関係は崩れる）は汚れのある肉厚の位置に 1 点だけ描きます。板の長さ・厚さ・幅とコイルの径は全工程で同じ縮尺で、工程ごとに長く・薄く・狭くなるのが見て分かります（長さと厚さは平方根ほどに縮めて比べやすくしています）。コイルは設備マスタの巻取方向（上／下）とライン方向（←／→）に合わせて回る向きを決め、最後端（尾）のベロは巻取り後の姿で描きます: 板が入る所（上巻き＝コイルの上・下巻き＝下）から上流の側（材料が来た側）へ回り込み、先はコイルの中心の高さにあります（例: 下巻きで右から左へ流れるライン＝← なら、下から右へ回り込み、先は右の中心の高さで上向き）。展開した板のオフ（前後の丈・両エッジ）は板と同じ厚さで、板の色にオフの色（丈＝橙・両エッジ＝青）を混ぜた半透明の面と点線の輪郭で描き、その外側に前工程までのオフをさらに淡く重ねます（頭側・尾側は巻き替えの回数で決まり、長さはその工程の全長に対する割合）。**仮の発生設備（計算の起点）**は左のメニューで一致率の高い順から選び（表の行を押しても切り替わります）、**視点（見る工程）**は上の行の ◀ ▶・一覧・「▶ 下流へ追う」でカメラだけを動かします（計算は変わりません）。
  - 検査計のある設備は LS3・LS4・DL2・TLV・NS1 です（配った版の初期値。起動したときに共有の設備マスタへ一度だけ当て、あとで直した値は戻しません）。
  - 「発見設備No.」は、取り込むと**実績の設備のうち検査計がある最後の設備**を自動で選びます（設備マスタの「検査計」が「有」の設備。一覧では「◉ 検査計」の印）。検査計のある設備が無いロットでは、最後の実績の設備を選びます。手ではどの設備でも選べ、手で選んだあとは表を直しても選び直しません（新しいロットを取り込むと自動に戻ります）。
  - 左の「解析条件」と「結果サマリ」は、表のタブに合わせて入力欄が分かれます。転写は汚れ位置A・B（実転写距離・一致工程数）、ピッチは発見ピッチ（候補ロール数）。発見設備・発見板厚・誤差は両方に出ます。隠れた欄の値は残り、タブを戻せばそのままです。
  - **入力＋ピッチ計算**: 転写とは別の計算として、板だけで描きます。発見ピッチが板厚の比で伸び縮みした各工程のピッチ（ロールの跡の間隔）と、径（ピッチ ÷ π）の合う候補ロールを示します。板は真ん中の仕切りで分け、左半分を入側（前の工程の出側ピッチ）・右半分を出側（その工程のピッチ）として、それぞれの間隔で跡を描きます。候補ロールも入側・出側に分けて出します。左のメニューは工程と候補ロールの数で、押すか表の行を押すとその工程を見ます。
  - 右の説明は既定で畳んでいます（「説明を開く」で開き、開閉は覚えます）。three.js は `app/static/vendor/three/` に同梱しています。

## 参照先（読みに行く場所）を変える

## マスタ管理

設備マスタ・ロールマスタは `data/equipment_master.json` / `data/roll_master.json`（各行に不変の `id` を持つ）で管理しています。旧 `*.csv` は移行前の参考資料として残していますが、アプリはこの JSON を正として読み書きします。

### 複数 PC でマスタを共有する

`config/appsettings.json` の `master_share.dir` に共有フォルダ（いまの設定: `\\nlmsrvngy03\工場内共有\検査データ\Masters`）を書くと、ロールマスタと設備マスタをそこに置いて、どの PC からも同じマスタを使います（空ならこれまでどおりこの PC の `data/`）。共有するマスタは `master_share.masters` で選べます。

- 読むのは PC ごとの手元の写しで、共有は数秒に1回「変わったか」を見るだけです。共有に届かなくても前の写しで計算できます（届くまでマスタの保存はできません）。
- 保存は WaveLog と同じく「錠を取る → 共有から取り直す → 当てる → 版を上げて置き換える」で行い、ほかの PC の変更を踏み潰しません。ほかの PC が保存中なら自動で待ちます。
- 開いてから保存するまでに同じ行がほかの PC で変わっていたら、相手の内容と自分の入力を並べて「相手の内容を読み込む／自分の内容で上書きする」を選べます。
- マスタ管理の見出しに、置き場（共有・手元のみ・届かない）と版・最終更新者が出ます。開いている間は、ほかの PC の変更を自動で読み込みます。

最初に共有フォルダを設定した PC が、その PC のマスタを最初の版として共有に置きます。仕組みは `program/docs/MASTER_SHARE_DESIGN.md`。

## 版とアクセス管理（WaveLog と同じ方式）

- **版**: 見出しの左上に `VER1.1.0` のように出ます。押すと更新履歴が開きます。版と履歴は `app/version.py`（配るたびに上げ、履歴の先頭に1件足す）。
  - **上げ忘れを止める仕組み**: `app/version.py` の `RELEASE` に「配った版と、そのときの配る物の中身の要約」を記録してあり、テスト（`tests/test_version.py`）がいまの中身と比べます。版を上げずにプログラムを変えるとテストが失敗します。
  - 配るときの手順: プログラムを直す → `APP_VERSION` を上げて `CHANGELOG` の先頭に1件足す → `program` フォルダで `python app_build.py --release`（版が上がっていない・履歴の先頭が今の版でなければ記録を断ります）→ テスト。まだ配っていない版を直しただけなら `python app_build.py --amend`。
- **最新版か**: 使っている PC は、共有フォルダ（マスタの共有フォルダの下の `presence_tpa`）に「だれが・どの PC で・どの版を」を 20 秒ごとに書きます。**最新版は、配る版（「アプリの配布」で決めた版）**です。配る版が決まっていなければ、使っている人たち（開発者を除く）の版のうちいちばん新しいもの。最新版と違う版で使っていると、版の札の横に知らせが出ます（使えなくはしません）。押すと次にすることが出ます。
- **アプリの配布**: 「マスタ管理」→「アプリの配布」。版を置く・配る版を決めるのは開発者・メンテナンス者だけです（ほかの人は見るだけ。ボタンを出さず理由を書きます）。切断中の PC は置けません。
- **だれか**: ログインID と PC 名は WaveLog と同じ取り方です（ログインID は Windows のログイン名で、設定では変えられません。PC 名は `config/appsettings.json` の `identity.pc_name` があればそれ、無ければ PC のホスト名）。見出しの区分の札（「一般ユーザー」など）を押すと、ログインID・PC名・マスタ編集が出ます。
- **権限**: 「マスタ管理」→「アクセス権限」で、ログインID・PC名の組ごとに決めます（どちらか空＝問わない）。当てはまる行が無い人は一般ユーザー（マスタ編集は「編集可」）です。
  - 権限区分: 開発者 > メンテナンス者 > 一般ユーザー > 設備作業者。自分の区分は自分では変えられず、自分と同格以上の区分は与えられません（開発者は例外）。管理者（メンテナンス者以上）がまだ居なければ、最初の1人は作れます。
  - 最初の管理者として、ログインID `satoshi-harada` を開発者に登録してあります（配った版の初期値。起動したときに共有のマスタへ一度だけ当てます）。
  - マスタ編集: 非表示（マスタ管理の入口を出さない）／閲覧のみ／部分的編集可（設備・ロールだけ書ける）／編集可（参照先・アクセス権限も書ける）。設備作業者は非表示までです。
- **利用状況**: 「マスタ管理」→「利用状況」（設備作業者以外）。いま使っている PC・使った記録・版（最新／要更新／対象外）を見られます。メンテナンス者以上は、使っている PC を理由を添えて**切断**できます（相手の画面に帯が出て、5 分間マスタへ書けなくなります。開発者の PC を切れるのは開発者だけ）。使わなくなった PC の記録も消せます。
- **使用の履歴**: 「利用状況」の「使用の履歴」で、起動ごとに **いつ・だれ（ログインID）が・どの PC で・どの版を・何分**使ったかを新しい順に見られます（版 3.3.0 から記録）。版が前の使い始めから変わった行には「更新 〈前の版〉 →」の札、いま使っている行には「● 使用中」が付きます。「PC ごとの状況」の各行の「履歴」で、その PC・ログインID の履歴だけを見られます。
  - 保存期間: 既定 365 日（30〜3650 日）。メンテナンス者以上が画面の「残す日数」で変えられ、全員の PC に効きます。古い記録は各 PC が使い始めるときに自分の分を自動で消し、「古い記録を今すぐ整理」で使わなくなった PC の分もまとめて消せます。「記録を消す」では、その PC の使用の履歴も消えます。
  - 置き場: 利用状況と同じ共有フォルダの `presence_tpa\sessions\<PC名@ログインID>\<年-月>.json`（その PC だけが書くので、ほかの PC とぶつかりません）。保存日数は `presence_tpa\settings.json`。

アプリの名前は `program/app/brand.json` の 1 か所で決めています。窓の題名・画面の見出し・ショートカット・配る ZIP とその中のフォルダ・リリースの名前は、すべてここから読みます。

## 異常ロット一覧（品質データから選ぶ）

WaveLog の品質データと同じ SQLite（既定 `\\Nlmsrvngy03\Read\【New】仕掛\台帳\SIKADEF.sqlite3`、「マスタ管理」の「参照先」で変えられます）の一覧です。**ロット番号を押すと**計算画面へ移り、検索欄へ入れて「検索」と同じ流れ（LotDsp の進度情報 → 取込 → 計算）で取り込みます。

- **読み方は WaveLog と同じ**: 共有のファイルを直接開かず、サーバーが手元（`%LOCALAPPDATA%\TransferPitchAnalyzer\db_cache`）へ写してから読みます。写し方は SQLite のバックアップ API（だめならコピー）→ `PRAGMA quick_check` で検査 → 毎回新しい名前（世代）で置き換え。共有は起動時と `lot_list.refresh_seconds`（既定 60 秒）ごとに「変わったか」を見て、変わったときだけ写します。共有に届かないときは前の写しで一覧を出し、見出しの札（元データ M/DD HH:MM）が「共有に届きません」と言います。札を押すと今すぐ取り直します。
- **元データが古いと警告します**: 毎日更新されるはずの元ファイルが、最後の更新から `lot_list.stale_hours`（既定 36 時間）を過ぎていたら、一覧の上に「元データが N日前から更新されていません」の帯を出し、右上の札も警告の色にします（最近の異常ロットは一覧に出ないため）。帯の「共有から取り直す」で今すぐ取り直せます。土日に更新しない運用なら 72 などに、0 にすると警告しません。
- 絞り込みは表全体に掛かります（1ページの500件だけではありません）。「以内」で1件も当たらないときは、その日付の列でいちばん新しい日付（と元の値）・今日・探した範囲・「この条件だけなら何件当たるか」を案内します。
- **日付の列は「今日から N日・週間・か月・年以内」でも絞れます**（値の8割以上が日付と読める列。`2026/09/28`・`26/09/28 23:48`・`20260928`・`2026年9月28日` などを日付として読みます）。
- **表示列は WaveLog と同じ**: 「表示列」の窓で、出す列・並び（ドラッグ）・表示名・幅（自動／手で決める／固定）・揃え・値の整え方（数値／日付・時刻／文字）・**計算列**（「＋ 列を作る」と式。WaveLog と同じ式の書き方）・**読み替えルール**（上から順に最初に当たったものを表示・色・試した結果・式にする。行の中の条件は「かつ」「または」でつなげ、「かつ」が先に結ぶ。先に決めたい所は「かっこ」でくくる。各行の「読み方」で組み立てを確かめられる）を決め、「保存」で確定します（閉じると元に戻る）。保存した設定・書き出し／読み込み・既定に戻すもあります。見出しはドラッグで並べ替え、右端の取っ手で幅、右クリックで隠す・幅・色・隠した列を戻す。「表の見せ方」で行間と表示件数。設定はこの PC に覚えます。
- **絞り込みは WaveLog の汎用フィルタと同じ**: 一覧を検索（どの列の字でも）／プリセット（登録した条件の組み合わせを入れ替え）／条件（効いている条件の確認・外す・☆で登録・条件を検索して足す・条件を作る・全部外す）／列で絞り込む（列と比べ方は覚え、値はその場だけ）／登録した条件とプリセット（組み合わせ名・いつも適用（固定））。比べ方は 12 種（含む・含まない・一致・不一致・前方一致・後方一致・より大きい・以上・より小さい・以下・空欄・空欄以外）で、数の比べ方は字で入っていても数で比べます。絞り込みはサーバーの SQL で行います。
- **並び・まとめ**（「表の見せ方」の「並び・まとめ」。表ごとに覚えます）: まとめる列を上の段から順に選びます（例: 設備 → ロット番号。いくつでも重ねられ、段の順はドラッグで入れ替え、段ごとに ▲ 小さい順／▼ 大きい順）。値が同じ行が続いて並び、まとまりができます。見せ方は小さな表の絵の札から選びます（押すとすぐ一覧がその形になります）: 「**並べるだけ**」（切れ目に線）／「**見出し行**」（まとまりごとに段の名前の札・値・件数・まとまりの中で同じ値。違う列は「n通り」。段が深いほど字下げ・札が淡い。押すと畳める）／「**繰り返しを省く**」（まとめた列の同じ値を1つにし、縦につながった面で見せる。値の横に件数）／「**見出し＋省く**」。省いた所は行にマウスを乗せると値が薄く出ます。まとめているあいだは件数の横に段の札が並び、▲▼ を押して入れ替え・× で外す・「＋ 段・見せ方」で足せます。見出しの右クリック「この列でまとめる」でも段を足せ、まとめた列の見出しを押すと ▲▼ が入れ替わります。その中の並びは今までどおり見出しを押して決めます（並べ替えのキーは段と合わせて4つまで）。いちばん上の段がロット番号なら、ロットをページの境目で切りません（ロットの順を「並べ替えの順」＝そのロットでいちばん上に来る行の順にもできます。以前の「ロット番号でまとめる」を使っていた PC は、この形で引き継ぎます）。
- **列の並びは自由**: 見出しをドラッグすると列を入れ替えられます（ロット番号の列も、どこへでも動かせます）。「表の見せ方」の「列と文字」で、**詰め具合**（ゆったり／ふつう／詰める／最も詰める を1押し）か、細かく **セルの余白**（左右 0〜14px）と **入り切らない字**（「…」で切る／記号なしで切る＝記号のぶん1〜2字多く見える／折り返して全部出す）を決められます。いまの一覧の値で「ふつう → いま」の見本を同じ幅の列に並べるので、どこで切れるかが見て分かります。**左に固定する列**は、一覧の先頭の列を並べた図で、押した列まで（4列まで）固定します。余白を詰めると、自動の幅もそのぶん詰まります。
- **行をダブルクリックするとカードで見られます**（「機能」で使う／使わない。既定は使う）: カードは見出しを掴んで動かし、**4辺と4隅**で大きさを変えられます（画面の端・ほかのカードへ吸い付きます。Alt を押すと吸い付きません。動かしているあいだは位置と大きさを数で出します。カードの中で Alt+矢印で 10px ずつ動かし、Alt+Shift+矢印で大きさ、Ctrl も押すと 1px ずつ）。「**📌 残す**」にしたカードは残り、次のダブルクリックは新しいカードに開きます（Ctrl＋ダブルクリックはいつも新しいカード。8枚まで）。開いているカードは一覧の件数の横の「棚」に札で並びます（押すとそのカードが前へ・📌・×・全部閉じる）。2枚以上のときは「**並べる ▾**」で並べ方を絵で選び（横に並べる・縦に積む・格子・右半分に＝一覧を見えたまま・重ねる）、「**違いを強調**」でほかのカードと値が違う項目に印を付けます。列数・文字の大きさ・空欄を隠す、「配置を編集」で項目の並べ替え（ドラッグ）・幅（1〜4枠・1行）・高さ（標準・2倍・3倍）・隠す。配置は表ごと、位置と大きさとともにこの PC に覚えます。◀ ▶（←→）で前後の行、同じロットの行は札で切り替え、「計算画面で開く」でそのロットを取り込みます。
- 見出しを押すと並べ替え（Shift＋押すでキーを足す・最大 4）。表が複数ある場合は右上で選べます（既定は `仕掛`、`lot_list.table` で指定可）。条件・並べ替えは表ごとにこの PC に覚えます。「いつも適用（固定）」はアプリを開いたときに当て、外した固定はアプリを開き直すと戻ります。

仕組みは `program/docs/LOT_LIST_DESIGN.md`。

## LotDsp（ロット問い合わせ）からの取込

ロット番号を入れて「検索」（または Enter）を押すと、LotDsp の進度情報（設備実績）を取り込みます。検索ボタンはこれ1つです（以前のサンプルデータの検索は削除しました）。

- **LotDsp の API をログインなしで読む道（版 1.4.0）**: LotDsp の画面が裏で呼んでいる API を、Cookie・パスワードなしで呼びます（LotSearch と同じ）。API の項目名は公開されていないので、画面（見えない Edge・LotDsp の窓・貼り付け）でロットを読めるたびに、同じロットを API でも引いて、画面の値と同じ値の項目を探して**学びます**。学び終えると、見出しの札が「データ元: LotDsp（API・ログインなし）」になり、「検索」は Edge を使わずに取り込みます。読めないときは今までの道へ自動で回ります。最初は学習中なので、今までどおりに数ロット読んでください（前オフ・後オフの値が入ったロットを含むと早く決まります）。止めたいときは設定 `lotdsp_import.api.enabled` を `false` にします。
- **応答にどんな情報が入っているかを調べる**（版 1.5.0）: 「マスタ管理」→「参照先」の最後の「LotDsp の項目を調べる」を開き、「応答に入っている項目の一覧」にロット番号を入れると、LotDsp の API の応答に入っている項目をすべて（道すじ・型・形・空でない件数・このアプリが使っているか）一覧にします。使っていない空でない項目は `unused_non_empty` にまとまります。既定は形だけ（数字は 9・英字は a）で、実際の製造・検査・受注データは含みません。この PC の画面で値も見たいときだけ、「値も出す」を選びます（その出力は外部へ渡さないでください）。
- **応答の項目が、画面のどの見出しかを調べる**（版 1.6.0）: 同じ「LotDsp の項目を調べる」の画面で行います（「← アプリへ戻る」で戻ります）。LotDsp で調べたいタブを開いて「名前を付けて保存」した HTML を選ぶと（タブごとに1つ・まとめて選べます）、同じロットの API の応答と値を照らして、「項目 ↔ 画面の見出し」の一覧にします。同じタブを**別のロット**でも保存して一緒に選ぶと、偶然の一致が消えて「確定」します。出力に値は含まれません。

- **社内（ログイン不要）では、このアプリだけで取り込めます。** アプリがこの PC の Edge を画面に出さずに動かし、LotDsp でロット番号を検索して進度情報を読みます（数秒）。取込結果の1行にマウスを乗せると「このアプリで直接」と出ます。
  - VPN などでログインが要るときは、見えない Edge は何も押さずに引き返し（このアプリはパスワードを扱いません）、**LotDsp の窓が開きます**（版 2.3.0）。その窓で ID・パスワードを入れてログイン（VPN の画面では「検索」）を押すと、続きの検索・取り込みはアプリが行います。ロット番号は窓の欄に入れてあります。ID・パスワードはこのアプリでは扱わず、ログインも押しません（覚えさせたいときは、その窓の Edge が覚えます。窓は専用のプロファイルで、いつもの Edge とは別です）。待つのは 5 分まで（`lotdsp_import.direct.login_wait_seconds`）で、待ちきれなければ理由を添えて貼り付けのダイアログを開きます。
  - ログインが要ったら、次からは最初から LotDsp の窓を使います（その日のあいだ）。LotDsp の窓はしばらく（30 分）残して使い回すので、ログイン済みならそのまま読みます（読み終わった窓はしまい、ログインが要るときだけ前に出します）。LotDsp の窓を使わないときは `lotdsp_import.direct.login_window` を `false` にします。
  - Edge を自動で見つけられない PC は、「マスタ管理」→「参照先」の「LotDsp を裏で読むブラウザ」に msedge.exe の場所を入れます。この読み方を止めるときは `config/appsettings.json` の `lotdsp_import.direct.enabled` を `false` にします。
- このアプリで読めない（LotDsp の窓でのログインを待ちきれない・LotDsp に届かない など）場合は、「検索」で取込ダイアログが開きます（理由をダイアログの最初に出します）。LotDsp の進度情報の画面を Ctrl+A → Ctrl+C して取込ダイアログへ貼り付けるか、保存した HTML を選びます。
- 設備名は設備マスタで引きます。LotDsp で別の名前・番号付きで出てくる工程（焼鈍の ANI・ANF・ANI1…、連続焼鈍の CAL・CAI・CAF…）は、設備マスタの「同一工程とみなす名前」に `ANI*, ANF*` や `CAI*, CAF*` のように登録しておくと、その設備として取り込みます（`*` は何文字でも・無くても、`?` は1文字。全角半角・大小は区別しない）。読み替えた工程は取込結果に出ます。番号に意味がある設備（L-1・L-2・LS3・LS4 など）には登録しないでください（ほかの設備の名前を横取りする書き方は保存時に断ります）。
- 実績の無い工程（まだ流れていない工程）は、設計の設備名だけを入れて取り込みます（板厚・重量などは空欄＝見て「未実績」と分かる）。この行は計算に入れず、発見設備にも選べません。
- 取込の結果は、検索欄の下の1行に「✓ ロット番号 n工程」と出ます。気にすべきことがあるときだけ、アイコンと件数が並びます（⚠ 取り込まなかった行・注意／◌ 未実績／⇄ 読み替え）。その行を押すと中身が開きます。出どころ・時刻はマウスを乗せると出ます。どの方法で読むかは「検索」ボタンにマウスを乗せると出ます。
- 設備マスタに無い設備の行は取り込まず、取込結果の ⚠ に出します。巻出し方向は初期値「上」が入ります（設備マスタが持つのは巻取方向）。

仕組み・取り込む項目・設定は `program/docs/LOTDSP_IMPORT_DESIGN.md`。テストは `program` フォルダで `python -m unittest discover -s tests -t .`。

## 以前のブラウザ版について（版 3.0.0 で外した）

以前は `Start.vbs` が Python を探してサーバー（127.0.0.1 のポート）を起こし、Edge で開くブラウザ版がありました。ポートが起こす不具合（プロキシ・ポートの取り合い・古いサーバーの居残り）と、二重の手入れを無くすため、デスクトップ版に一本化しました。VPN でログインが要るとき Edge 拡張 LotData-Link が読んでいた道は、LotDsp の窓（ログインは利用者・続きはアプリ）に置き換わっています。隣の exe を開くだけになっていた `Start.vbs` も、版 3.1.0 で外しました（入口は exe だけ。新しい版へは exe が引き継ぎます）。

## 窓（desktop/）を作る・確かめる（開発する人へ）

版 3.9.0 から、窓（Rust・Tauri）の元をこのリポジトリの `desktop/` に置いています（WaveLog の窓を元に作り直しました）。
いま `desktop/` が受け持つのは、窓・起動画面・1つだけ起動・静的ファイル・中身（Python）の監督と起こし直し・外のリンク・終了と、
異常ロット一覧の問い合わせ・品質データの写しです（Python と同じ答えであることを `cargo test` の突き合わせで確かめます）。
更新・配布・この PC へ写す・ショートカットは、順に `desktop/` へ移します（窓は受け持つ仕事を起動のときに中身へ伝え、中身は伝えられなかった仕事を自分で受け持ちます）。

- 作る: `cd desktop && cargo build`（Linux は `libwebkit2gtk-4.1-dev` などが要ります。`.github/workflows/ci.yml` を参照）。exe は上へたどって `program/sidecar.py` を探します。
- 自己診断: `TPA_SELFTEST=<結果のファイル> desktop/target/debug/Defect-Analyzer` で起こすと、本物の窓の中で 27 項目を確かめて結果を書き、終わります（CI が Linux と Windows で毎回流します）。
- アイコンは `program/app/app_icon.py` が描きます（作るたびに `desktop/build.rs` が書き出します）。
- 一覧の速さ: `cargo run --release --example lotbench -- <品質データ>` と `python program/tests/lotlist_bench.py <品質データ>` が同じ問い合わせを測ります。
